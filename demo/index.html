版本数据库 · Version-Controlled Database

数据，应该像代码一样
有版本、分支和合并

PollyDB 让每一次数据变更都成为一笔可审计的 commit。
支持时间旅行、分支并行审核、一键回滚 —— 这是 MySQL 做不到的事。

核心能力

不是数据库插件，不是 ORM 层 —— 是存储引擎原生支持的版本语义。

⏱

时间旅行

点击任意历史 commit，整张表瞬间回放到那个时间点的完整快照。不是查询日志，是真正的状态回放。

⑂

分支与合并

多人并行审核同一份数据，各自在独立分支上修改，最终 merge 回主线。冲突可见、可解、可追溯。

⟲

一键回滚

数据被误改？一条命令恢复到任意历史版本。回滚本身也是一笔 commit，审计链永不断裂。

🔍

完整审计链

每笔 commit 记录 who / when / what / why。不是 trigger 写的 audit_log 表，是存储结构本身不可篡改。

工作原理

像用 Git 一样操作数据 —— 因为底层就是不可变树 + 内容寻址。

1

Typed DDL 建模

用 YAML 声明表结构、索引与能力。类型安全，schema 即文档。

schema_version: 1
tables:
  - name: contracts
    primary_key: [doc_id]
    columns:
      - name: amount
        type: i64
      - name: status
        type: string
2

每次修改 = 一笔 Commit

INSERT/UPDATE/DELETE 都生成不可变快照。自动记录作者、时间、消息。

$ pollydb commit -m "approve: 合同审批通过"
[main f2a8b1] approve: 合同审批通过
  author: reviewer-zhang
  changed: status "pending" → "approved"
3

分支并行 · 合并收敛

法务和财务各开分支审核，互不干扰，最终 merge 回 main。

$ pollydb branch review/legal
$ pollydb checkout review/legal
$ pollydb commit -m "fix: 违约条款修订"
$ pollydb checkout main
$ pollydb merge review/legal ⑂

为什么不用 MySQL？

传统数据库的版本能力是"打补丁"，PollyDB 是"原生支持"。

能力MySQL / PostgreSQLPollyDB
数据回滚到任意时间点❌ 需要 binlog 手动恢复✓ 一条命令
多人并行修改同一份数据❌ 锁冲突 / 最后写入胜出✓ 分支隔离 + merge
完整变更审计⚠️ trigger / audit_log 表✓ 存储层不可篡改
查看"上周三的数据长什么样"❌ 需要备份恢复✓ 时间旅行秒级回放
变更可 diff 对比❌ 无✓ pollydb diff commit1..commit2
Schema 即代码⚠️ migration 文件✓ Typed DDL YAML
